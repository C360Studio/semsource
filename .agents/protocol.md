# Shared Work Protocol (Claude, Codex, and Gemini)

ATeam is an opinionated experimentation lab primarily grounded in Go development. Initialization uses the same templates for all project languages; it does not detect language support or create a Taskfile. Review and adapt these instructions before adoption. Go mutation checks require non-test .go source; verification targets belong to the adopting project. Shortcut scanning covers only .go, .ts, .js, .svelte, .sh, .yml, and .yaml files (excluding Go tests and .test.ts files). Other languages are not validated as complete workflows. Ponytail modes change injected guidance, not model settings or guaranteed compliance. Benchmark self-tests validate reference fixtures, not improved agent performance.

Canonical protocol for `ateam` and repositories bootstrapped with `ateam init`. `AGENTS.md` and `CLAUDE.md` point here and inline the four workflow gates (**Clarify, Claim, Merge, Close**).

## 1. Hybrid State Architecture (GitHub + Gitea + OpenSpec + Local Cache)

Shared truth lives in the repository's versioned code, `openspec/` specs and changes, git worktrees, and the repository's remote forge (**GitHub** or **Gitea**), backed by a fast gitignored local cache (`.ateam/state.json`) so CLI lifecycle hooks execute in `<10ms` without blocking on network calls:

- **What is wanted & decided (GitHub & Gitea):** Issues with labels `type:epic`, `status:needs-decision`, `status:blocked`, `class:flake`.
- **Who has claimed what:** A draft PR on an agent-prefixed branch (`claude/<topic>`, `codex/<topic>`, `gemini/<topic>`) in its own worktree (`git worktree list`), with `Closes #n` or `Addresses #n`.
- **Target state, task truth & holds (`openspec/`):** `openspec/specs/<capability>/spec.md` holds current truth; `openspec/changes/<id>/` holds in-flight changes validated by `task spec:check` and `task spec:queue`.
- **Intentional shortcuts (`// shortcut:`):** Deferred complexity is marked inline in source code as `// shortcut: <the limit>, <when to upgrade>` and scanned live by `ateam state debt`.
- **Session handoff & pre-compaction cache:** `ateam state handoff` snapshots live git branch/HEAD/dirty status, OpenSpec queue/holds, forge issues/PRs, and `// shortcut:` items alongside the 5 semantic handoff fields (`Goal`, `Addresses`, `Constraints`, `Done when`, `Checks to run`).

## 2. Work Lifecycle & Definition of Done

1. **Clarify:** Before mutating state on an underspecified request, inspect the tree first, then confirm Deliverable, Scope/non-goals, Definition of Done, and Stop boundary. For non-trivial work the default Stop boundary is proposal approval: a one-page `proposal.md` (≤ 60 lines; detail goes in `tasks.md` or `design.md`) with an empty `Approved-by:` line, and a first task carrying `Hold: OPEN-Q proposal awaits owner approval` until the owner fills `Approved-by: <name> (<YYYY-MM-DD>)` and removes the hold in the same edit; the agent stops at the hold and hands off. A non-trivial change also declares its track: `design` when it adds a spec Requirement, touches more than one capability under `openspec/specs/`, adds exported surface reachable from an adopting repository, or touches a boot path, durability/ack behavior, or a gate file, otherwise `quick` with no `design.md`. On `design`, the `design` skill (`.agents/skills/design/SKILL.md`) drafts `design.md` in OpenSpec's `spec-driven` sections (≤ 120 lines; `task spec:check` warns past it), and the one approval hold covers `proposal.md` and `design.md`.
2. **Claim:** Create or switch to an isolated worktree at `.worktrees/<agent>-<topic>`, the gitignored directory inside the repository, unless the host creates it for you (Enjoy's `move_to_worktree`, herdr, T3 Code), on an agent-prefixed branch (`claude/…`, `codex/…`, `gemini/…`; T3 Code names its own `t3/<topic>`), backed by a draft PR on GitHub or Gitea.
3. **Execute (Ponytail Decision Ladder):** Take the smallest complete change that solves the task, reuse stdlib/existing code, add a focused test using an independent oracle for every non-trivial branch/parser, and tag deliberate limits with `// shortcut: <the limit>, <when to upgrade>`.
4. **Verify (4-Gate Definition of Done):** `task verify` green, `ateam doctor` parity green, `ateam bench --selftest` green, `implemented-by:` and a not-weaker `reviewed-by:` recorded (`task merge:check -- <pr>`) in a PR comment starting `reviewed-by: <agent> (<model>, <effort>)` and naming one PR commit as `Reviewed at <sha>` (template: `.agents/contracts/reviewer.md`; a later commit that is not a clean merge of `main` or docs-only needs a new record), and Ponytail exit summary stated.
5. **Handoff or Land (Close):** At a session boundary or before context compaction, run `ateam state handoff` (or `/handoff`) to record the 5-field pickup prompt. When a PR lands an OpenSpec change, the archive move (`openspec/changes/<id>/` → `openspec/changes/archive/<date>-<id>/`) is a commit on the branch before the PR is marked ready, and the change's `Hold: OPEN-Q proposal awaits owner approval` must be gone before that move; merging with a completed unarchived change is a Close-gate miss, not a follow-up. Mark the PR ready and arm auto-merge (`gh pr merge --squash --auto`; on Gitea, `POST /repos/{owner}/{repo}/pulls/{n}/merge` with `{"do":"squash","merge_when_checks_succeed":true}`); the merge fires when the required check is green on an up-to-date branch, and arming it past a previously red required job needs the cause fixed or an owner waiver. A code PR then waits for its review, and the review policy's `review_launch` says who starts the reviewer: under `manual` (the default) stop at ready-for-review and hand off, and a person or a scheduled workflow starts it; under `agent`, run `ateam review request <n>`, which prints the eligible reviewer runs and, with a host manifest in `.agents/hosts/`, starts the reviewer or names the host tool to call. The record then shows on your worktree's pickup line after `ateam state sync` runs in your own checkout, which keeps its own cache; `ateam state pickup` alone skips the fetch while that cache is under 30 seconds old. Once the merge has landed, remove the worktree you claimed and delete its remote branch; `ateam state prune` does both for every clean, merged worktree on your agent prefix that no other session holds or handed off in the last 30 minutes (`--force` overrides that; `--dry-run` first lists what it would remove). The `main` run is informational: a red one after a green up-to-date PR run is a tracked issue, not a reason to keep the worktree. Review checkouts (`.worktrees/<agent>-review-pr-<n>`, detached; `ateam state prune` also removes them once the PR is closed) are removed when the review record comment is posted. Pickup labels every merged and PR-less worktree; a finished worktree older than a day is yours to explain or remove.

## 3. Mutation & Property-Based Testing (PBT) Discipline

1. **Independent oracle & wrong behavior first:** State the correct behavior and one plausible wrong behavior; compute expected outcomes from an independent oracle or reference model, never by repeating production logic.
2. **Non-destructive mutation check (`task mutate:check` / `ateam mutate`):** Never run `git checkout --`, `git restore`, `git stash`, `git clean`, or `git reset --hard` to undo a mutant. Use `task mutate:check` (`go test -overlay` on a copy outside the repo) or `cp` + `shasum -a 256` before/after, and report `detection`, `survivor`, `invalid`, or `inconclusive`.
3. **Generated checks (Fuzz targets & PBT):** When touching interacting inputs, stated laws (round-trip, idempotence), or order-dependent histories, record whether `testing.F` / PBT is used or why named examples suffice, verify boundary reach and assertion activation, and compare histories against a test-owned reference model.
## Test-to-spec attribution

Run `ateam test-spec` (or `task test:spec`) to deterministically validate every Go `Test`, `Fuzz`, and executable `Example` declaration and every Vitest `it`/`test` declaration. Attach one or more line comments directly to the declaration, naming existing repository-relative specifications and exact requirement headings:

```go
// spec: openspec/specs/harness/spec.md#Requirement: OpenSpec queue and stray Hold detection
func TestOpenSpecQueueAndCheck(t *testing.T) {
    // assertions
}
```

Multiple requirements use separate `// spec:` lines. Go subtests inherit the top-level declaration; each Vitest test needs its own immediately preceding comment, without inheritance from `describe`. Missing, malformed, dangling, and escaping references fail the gate. Keep references current when requirements move or are renamed. The checker excludes benchmark functions and fixture source inside string literals; generated test source is not exempt. Dependency, VCS, worktree, and build-output directories are excluded. In a repository with uncited legacy tests, `ateam test-spec --base <ref>` reports a missing citation only for tests whose lines or attached comments changed since the merge base of `<ref>` (uncommitted and untracked files included); broken citations still fail everywhere, and an unresolvable `<ref>` or a shallow clone exits 2 ([brownfield guide](../docs/brownfield.md#5-gate-new-tests-first)).

A test may instead (or also) carry `//aip:verifies <IDs>` (no space after `//`; the spaced form is a diagnostic), naming one or more space-separated scenario IDs. Each ID resolves when a line outside code fences in a canonical `openspec/specs/*/spec.md` or in-flight `openspec/changes/<change>/specs/*/spec.md` (never `archive/`) is `#### Scenario: <ID>` followed by a space or end of line; an empty or unknown ID fails.

Vitest scanning requires Node and TypeScript installed at ui/node_modules/typescript in the target repository. Supported filenames end in .test or .spec plus .ts, .tsx, .js, or .jsx; .mjs/.cjs and other frameworks are outside this gate. Direct Vitest imports (including aliases), namespace calls, globals, modifiers, and parameterized declarations are recognized; arbitrary wrapper modules and runtime expansion counts are not covered. A blank line detaches a citation; block comments do not count as citation lines. Directory symlinks are not followed and symlink test files are rejected. The checker includes untracked supported tests and all Go build tags. It skips .git, .worktrees, node_modules, vendor, .svelte-kit, .enjoy-logs, ui/build, internal/web/dist, coverage, bin, benchmarks/runs, and .ateam. Other testdata files are not exempt.

Attribution validates syntax and reference existence, not whether assertions prove the requirement or whether all specifications have tests. Review must assess those claims separately. The current supported languages are Go and Vitest JavaScript/TypeScript; adopting projects must provide appropriate attribution enforcement for other frameworks and languages.

## 4. Configured model review

The merge gate needs a separate read-only reviewer run not weaker than every implementer by model tier, then effort band, as .agents/review-policy.json declares; an equal tier and band passes, so it has no ceiling and no exception. Cross-provider review is required only when the policy sets cross_provider; reasoning effort is not model strength. A later commit needs a new review record unless the reviewer contract's Record section exempts it. A policy declaring only tiers and bands configures no routes: ateam review route then exits non-zero by design, and the rest of this section does not apply.

Optional route path. Install owner-approved models, routes and forge author/owner logins with ateam review setup --policy FILE. No universal model ranking is supplied. With routes configured, run ateam review route before implementation and revalidate all actual model escalations. Native clients must be launched with the selected model/effort; role cards do not pin or attest runtime identity.

On that path the reviewer must outrank every actual implementer, and any new head or policy revision invalidates evidence. If no stronger model exists, approval blocks without an explicit owner exception scoped to head/reviewer/policy. Independence, current evidence, configured checks and verdict remain required.

Use ateam review check --pr N --record-comment ID with optional --exception-comment ID. The gate reads policy only from the forge-verified current repository default branch, accepts only configured review/owner accounts, and refuses stale or known edited evidence. All paths require review. Shared logins, model/session claims and same-timestamp comment edits remain attestation limits; do not claim runtime or body authorship is proven.
