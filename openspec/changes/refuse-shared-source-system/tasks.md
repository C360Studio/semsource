## 3. Collision check

- [x] 3.1 `sourcespawn.CheckSystemCollisions(components)` with the D1 key and the D2 pin exception; unit table from design "Testing". Landed in `internal/sourcespawn/collisions.go:179` (tests `collisions_test.go`). Deviation from the D3 one-argument shape: it takes `[]PlannedComponent{Instance, Config, Pin}`. A component config cannot say it is a pin (`SourceEntry.InstanceSuffix` is `json:"-"`), and a map keyed by instance cannot hold two file entries that build one instance over different roots (two ast sources under one project with no version both build `ast-source-<project>`, and `sourceComponents` keeps only the last). Pins: from `InstanceSuffix` where entries are built (file, `CheckSourceCollisions`), and at boot from the discovery record's `submodule` components (see 3.3). Finding: absolute paths slug to their base name, so two path-derived sources such as `/a/docs` and `/b/docs` now collide and are refused, which is the #349 class and intended.
- [x] 3.2 `Config.Validate` builds specs for the file's sources and calls the check (`semsource validate`, `semsource run`); repo sources needing a checkout are left to boot. Placement deviation: `config.Validate` cannot call sourcespawn (sourcespawn imports config), so `sourcespawn.CheckSourceCollisions` (`collisions.go:206`) runs from `cli.Validate` (`cli/validate.go:24`) and from `loadAndExpandConfig` before NATS (`cmd/semsource/run.go:292`, over the expanded sources). `repoSpecs` needs no checkout for a single-branch repo (paths derive from the URL; only the git leaf, outside the rule, resolves a remote), so validate checks those; only multi-branch repos, whose branches are listed from a checkout, are left to boot.
- [x] 3.3 Boot calls the check over the planned set (file, desired manifest, discovered pins) before spawning; a collision stops boot naming the instances. `checkBootCollisions` (`cmd/semsource/shared_system.go:20`), called at `run.go:180` right after `admitDiscovered`, over the configuration in effect (the exact set the manager spawns). Pins are the names the discovery record files under kind `submodule`, which also covers pins a failed discovery kept from the previous boot. Discovery's KV writes for this boot land before the check; nothing spawns. Open finding for the owner: D2 refuses a pin plus a standalone source at the same SHA, but `docs/QUICKSTART.md` (quickstart:multi, steps 2 and 4), `openspec/specs/onboarding-quickstart/spec.md` "Shared code dedups across sources" and ADR-0012 ("or registered standalone") document exactly that pair as supported dedup. The first boot of that track admits no pin (the remote clone does not exist yet), so the e2e likely stays green, but every later boot of that config is refused. Not changed here: it needs a ruling (keep D2 and rewrite the quickstart demo, or admit a standalone source whose project and version equal a pin's).
- [x] 3.4 `AddWithChecker` calls the check over existing plus pending specs (same-instance re-adds excluded); refuses with `CodeValidationFailed`; nothing persisted. `checkAddCollisions` (`collisions.go:256`), called at `sourcespawn.go:180` before any write. Refinement of "same-instance re-adds excluded": excluding whole instances would admit the spec scenario's case (another path, same project, builds the same instance and would silently replace it). The exclusion is per root instead: a registered root the add rebuilds under the same instance and system is the same writer; a registered root the add would drop stays and collides. A refresh that adds a doc root keeps working. Collisions among registered sources alone are not this add's and are left to boot.

Also unreachable now and left for task 4: doc-source's `rootsShareIDs` shortcut (`processor/doc-source/component.go:168`).
